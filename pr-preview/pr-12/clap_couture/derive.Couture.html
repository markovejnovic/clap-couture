clap_couture

Derive Macro Couture 

#[derive(Couture)]
{
    // Attributes available to this derive:
    #[category]
    #[couture]
}
Expand description

Enable clap-couture on your clap subcommand enum.

  • #[couture(categories = { "key" = { title = "...", description = "..." }, ... })] on the enum declares the categories in display order. title and description are optional. title is the heading as printed, colon included ("Deploy:", "部署："); without one, the heading is the key and a colon.
  • Similar to clap, you can pass arbitrary expressions to any field, eg. title = t!("deploy"), which can enable localized text.
  • #[category("key")] on a variant files it under that category. Naming a category the enum neither declares nor inherits is a compile error, unless it declares and inherits none.
  • A #[command(flatten)] variant or field brings its type’s categories along, after the enum’s own. On a label both use, the enum’s declared title and description win. A flattened subcommand enum must derive Couture too; a flattened Args type need not.
  • With the interactive feature, #[couture(prompt)] or #[couture(prompt = "...")] on a field asks for that arg when the user leaves it out.
  • With the interactive feature, #[couture(confirm)] or #[couture(confirm = "...")] on a bool flag asks to go ahead after every prompt, unless the flag is passed. A no, or no terminal to ask on, fails the parse. {arg} in the question stands for that arg’s value.
  • #[couture(messages = { usage = ..., options = ..., none = ... })] replaces the text couture prints itself, eg. to localize it. Any of the three may be left out. It applies on the type you parse, or the one you pass to with_couture.

§Examples

Group subcommands under headings:

use clap::{Parser, Subcommand};
use clap_couture::{Couture, CoutureParser as _};

#[derive(Parser, Couture)]
struct Cli {
    #[command(subcommand)]
    cmd: Cmd,
}

#[derive(Subcommand, Couture)]
#[couture(categories = {
    "everyday" = { title = "Everyday:", description = "Commands you'll reach for daily" },
    "admin" = {},
})]
enum Cmd {
    /// Deploy the current project
    #[category("everyday")]
    Deploy,
    /// Rotate the API keys
    #[category("admin")]
    RotateKeys,
    /// Print the version
    Version,
}

Cli::couture_command().print_help().unwrap();
Usage:
  tool <COMMAND>

  version      Print the version

Everyday:  Commands you'll reach for daily
  deploy       Deploy the current project

admin:
  rotate-keys  Rotate the API keys

Options:
  -h, --help  Print help

A nested subcommand enum can file its variants under its parent’s categories:

use clap::Subcommand;
use clap_couture::Couture;

#[derive(Subcommand, Couture)]
#[couture(categories = { "admin" = { title = "Administration:" } })]
enum Cmd {
    #[category("admin")]
    #[command(subcommand)]
    Keys(KeysCmd),
}

#[derive(Subcommand, Couture)]
#[couture(inherit = ["admin"])]
enum KeysCmd {
    /// Rotate the API keys
    #[category("admin")]
    Rotate,
}

Localize the text couture prints itself:

use clap::Parser;
use clap_couture::{Couture, CoutureParser as _};

#[derive(Parser, Couture)]
#[couture(messages = { usage = "Verwendung:", options = "Optionen:" })]
struct Cli {
    #[arg(long)]
    verbose: bool,
}

let help = Cli::couture_command().render_help().to_string();
assert!(help.contains("Verwendung:"));

With the interactive mode, you can add a couture prompt to ask the user for input interactively.

use clap::Parser;
use clap_couture::{Couture, CoutureParser as _};

#[derive(Parser, Couture)]
struct Cli {
    /// Region to deploy to
    #[arg(long)]
    #[couture(prompt)]
    region: String,

    #[arg(long)]
    #[couture(prompt = "Tail the logs afterwards?")]
    follow: bool,
}
