Crate clap_couture

Expand description

Haute couture for your command line.

clap_couture is a semi-opinionated extension set for clap that:

  • Organizes CLI subcommands in categories, improving readability and making your CLIs less intimidating.
  • Interactive input for flags.
  • Markdown support.

See examples/99-full-example.rs.

§Getting Started

This section will provide you with a tour guide through clap_couture’s features. For some more in-depth examples, please have a look at the examples directory. I’ve put some good love into making those examples as helpful as I can.

§Categories

As CLIs grow, the total set of subcommands grows very quickly, and a first-time user running your application foobar --help, sees a massive wall of text. Making your application less intimidating makes it more accessible to the beginner user, which makes it more inviting and friendly.

With clap:

Commands:

  login     Sign in to your account
  logs      Tail live logs
  rollback  Roll back to a previous release
  search    Search your deployment history

  status    Show recent activity

  -h, --help  Print help

With clap-couture:

Deploy and manage your apps from the terminal

Usage: orbit <COMMAND>

  logs      Tail live logs
  search    Search your deployment history
  status    Show recent activity

Deploy:
  deploy    Ship the current project
  rollback  Roll back to a previous release
  secrets   Manage environment secrets

Account & sync:  Who you are, on every machine
  login     Sign in to your account
  sync      Sync settings across machines

  help      Print this message or the help of the given subcommand(s)

Options:
  -h, --help  Print help

To get started with this feature, take your existing code:

#[derive(Parser)]
struct Cli {
    #[command(subcommand)]
    cmd: Cmd,
}

#[derive(Subcommand)]
enum Cmd {
    /// Ship the current project.
    Deploy,
    /// Sign in to your account.
    Login,
    /// Tail live logs.
    Logs,
    /// Roll back to a previous release.
    Rollback,
    /// Search your deployment history.
    Search,
    /// Manage environment secrets.
    Secrets,
    /// Show recent activity.
    Status,
    /// Sync settings across machines.
    Sync,
}

Derive Couture on your command and organize your commands in different categories.

use clap_couture::{Couture, CoutureParser as _};

#[derive(Parser, Couture)]
struct Cli {
    #[command(subcommand)]
    cmd: Cmd,
}

#[derive(Subcommand, Couture)]
#[couture(categories = { "everyday" = {}, "deploy" = {}, "account" = {} })]
enum Cmd {
    /// Ship the current project.
    #[couture(category = "deploy")]
    Deploy,
    /// Sign in to your account.
    #[couture(category = "account")]
    Login,
    /// Tail live logs.
    #[couture(category = "everyday")]
    Logs,
    /// Roll back to a previous release.
    #[couture(category = "deploy")]
    Rollback,
    /// Search your deployment history.
    #[couture(category = "everyday")]
    Search,
    /// Manage environment secrets.
    #[couture(category = "deploy")]
    Secrets,
    /// Show recent activity.
    #[couture(category = "everyday")]
    Status,
    /// Sync settings across machines.
    #[couture(category = "account")]
    Sync,
}

You need to call CoutureParser::couture_parse instead of Parser::parse, and you’ll get the organized --help menu.

§Markdown Support

clap_couture also has support for markdown with the markdown feature flag, which is off by default. Help text is then CommonMark, so *, _ and <...> mean what they do there.

use clap::{Parser, Subcommand};
use clap_couture::Couture;

#[derive(Parser, Couture)]
struct Cli {
    #[command(subcommand)]
    cmd: Cmd,
}

#[derive(Subcommand, Couture)]
enum Cmd {
    /// Ship the **current** project.
    Deploy,
    /// Sign in to *your* account.
    Login,
}

This results in:

Usage: markdown <COMMAND>

  deploy  Ship the current project
  login   Sign in to your account
  help    Print this message or the help of the given subcommand(s)

Options:
  -h, --help  Print help

§Interactive Input

Finally, clap-couture lets you easily add interactive input, straight into your clap structs. Often enough, you might want to express the idea of “if the user doesn’t provide a CLI argument, we should ask the user for input on stdin”. With clap_couture, that’s just a tiny macro away.

You can decorate your argument flag fields:

use clap::{Parser, ValueEnum};
use clap_couture::{Couture, CoutureParser as _};

#[derive(Parser, Couture)]
struct Cli {
    #[arg(long)]
    #[couture(prompt = "Which app?")]
    app: String,

    #[arg(long)]
    #[couture(prompt = "Tail the logs afterwards?")]
    follow: bool,

    #[arg(long, value_enum)]
    #[couture(prompt = "Which region?")]
    region: Region,

    #[arg(long, default_value_t = 2)]
    #[couture(prompt = "How many replicas?")]
    replicas: u16,
}

#[derive(Clone, Debug, PartialEq, ValueEnum)]
enum Region {
    Apac,
    Eu,
    Us,
}

let cli = Cli::couture_parse();

This results in support for interactive input:

§Neat features

  • #[couture(prompt)] asks the field’s doc comment, and #[couture(prompt = "...")] asks whatever you write instead.
  • #[couture(prompt)] on an arg with a default_value prompts the user, pre-filling the input form.
  • Couture parses rich types the same way clap does in interactive mode. Types like u16 (or any FromStr type, really) get correctly parsed, even in interactive mode.
  • #[couture(prompt)] will avoid inquiring about fields the user passed either through the CLI flags or the environment.
  • #[couture(prompt)] only queries the input field if stdin and stderr are terminals. If the user is not in a terminal (e.g. scripts, CI), couture will skip interactive prompts.

§Confirmation

#[couture(confirm = "...")] on a bool flag asks before going ahead. A yes sets the flag, a no exits with status 1. Passing the flag skips the question, and without a terminal it must be passed, so a parse that returns always has the flag set. {arg} in the question stands for that arg’s value; {{ and }} are literal braces.

use clap::Parser;
use clap_couture::{Couture, CoutureParser as _};

#[derive(Parser, Couture)]
struct Cli {
    #[arg(long)]
    name: String,

    #[arg(long)]
    #[couture(confirm = "Delete {name} for good?")]
    force: bool,
}

let cli = Cli::couture_parse_from(["delete", "--name", "web", "--force"]);

§Secrets

#[couture(prompt, secret)] on a SecretString field asks without echoing the answer, just like sudo. Note that this flag is refused on the CLI, by default, as that is considered unsafe. secret(allow_argv) allows it.

A value from its env var is used without asking, and --help hides it.

use clap::Parser;
use clap_couture::{Couture, CoutureParser as _, interactive::secrecy::SecretString};

#[derive(Parser, Couture)]
struct Cli {
    /// Deploy token.
    #[arg(long, env = "ORBIT_TOKEN")]
    #[couture(prompt, secret)]
    token: SecretString,
}

let cli = Cli::couture_parse();

§Piped input

#[couture(stdin)] reads stdin into an arg the user passes -, so post --message - takes the message from a pipe or a file. #[couture(stdin(piped))] takes a pipe unasked as well: echo hi | post works like post --message hi. Only a pipe is read that way, so a terminal, a file or /dev/null on stdin never blocks the parse, but a pipe nobody writes to does, as under ssh host cli; read the warning before choosing it. Beside prompt, the arg is asked when nothing is piped; beside secret, it works like docker login --password-stdin.

use clap::Parser;
use clap_couture::{Couture, CoutureParser as _};

#[derive(Parser, Couture)]
struct Cli {
    /// Message to post.
    #[arg(long)]
    #[couture(prompt, stdin(piped))]
    message: String,
}

let cli = Cli::couture_parse_from(["post", "--message", "hi"]);

An example of this interaction is:

See examples/10-interactive-stdin.rs.

Only one arg on a command may take stdin, as stdin can only be read once. See the interactive module for the details.

§Dash input

#[couture(prompt(dash))] asks for an argument interactively if the user passes - as the command line flag.

ⓘ
#[arg(short, long)]
#[couture(prompt(dash), editor)] // `commit -m -` opens your $EDITOR
message: Option<String>,

#[arg(long)]
#[couture(prompt, secret, stdin)] // `login --password -` reads stdin
password: SecretString,

See examples/11-interactive-dash.rs, and the interactive module for the details.

§Custom interactive input

Some questions only make sense after the parse. CoutureParser::prompter asks them in the same UI, styles and behavior as clap-couture does. Prompter::secret asks for a secret without echoing it, and with interactive-editor, Prompter::editor asks in the user’s $EDITOR.

use clap::{Parser, ValueEnum};
use clap_couture::{Couture, CoutureParser as _};

#[derive(Parser, Couture)]
struct Cli;

#[derive(Clone, ValueEnum)]
enum Engine {
    Postgres,
    Sqlite,
}

if let Some(prompter) = Cli::prompter()
    && prompter.confirm("Add a database?", true)?
{
    let engine = prompter.select::<Engine>("Which engine?")?;
}

§Backends

You can pick from three interactive backends:

  • interactive-cliclack uses the cliclack crate to ask the user for input.
  • interactive-inquire uses the inquire crate to ask the user for input.
  • interactive-dialoguer uses the dialoguer crate to ask the user for input.

§Internationalization

clap-couture allows you to accept any expression instead of plain strings, which can be useful to localize with something like fluent.

ⓘ
#[couture(messages = {
    none = fl!("none-opt"),
    options = fl!("options-opt"),
    usage = fl!("usage-opt"),
})]
struct Cli {
    #[arg(long, value_enum)]
    #[couture(prompt)]
    region: Option<Region>,

    #[command(subcommand)]
    cmd: Cmd,
}

#[couture(categories = { "deploy" = { title = fl!("deploy-opt") } })]
enum Cmd {
    #[couture(category = "deploy")]
    Ship,
}

Cli::couture_command().print_help().unwrap();

For a full example, see examples/04-interactive-i18n.rs.
