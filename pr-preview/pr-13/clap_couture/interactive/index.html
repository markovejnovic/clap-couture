Ask on the terminal for prompted args the user left out.

Mark a field with #[couture(prompt)] to ask its help text, or #[couture(prompt = "...")] to ask something else. When the user leaves the arg out and stdin and stderr are terminals, CoutureParser’s entry points ask for it, then parse the answer as if it had been typed. Without a terminal, parsing behaves exactly like clap.

use clap::Parser;
use clap_couture::{Couture, CoutureParser};

#[derive(Parser, Couture)]
struct Cli {
    /// Region to deploy to
    #[arg(long)]
    #[couture(prompt)]
    region: String,
}

let cli = Cli::couture_parse_from(["deploy", "--region", "eu"]);
assert_eq!(cli.region, "eu");

A prompted arg that has a default is asked with the default pre-filled. An optional arg answered with nothing stays unset. An arg that takes many values, like a Vec<T>, is asked as a multi-select when it has possible values, and otherwise one value at a time until an empty answer. An arg passed on the command line or through its env var is never asked, and neither is one that conflicts with a passed arg or an earlier answer. An arg required through required_unless_present or a required ArgGroup is asked as required, and an empty answer is refused; in a group of prompted args, only the last one asked is. clap can’t lift required_unless_present_all or required_if_eq from an arg, so when one of those fires, parsing fails with clap’s error before anything is asked. Answers are not re-checked against requires and similar rules between args.

#[couture(confirm)] on a bool flag the user left out asks whether to go ahead, after every other prompt, with each {id} in the question replaced by arg id’s value. A yes sets the flag; a no fails the parse. Without a terminal, the flag must be passed, as if it were required.

§Answering in the editor

With the interactive-editor feature, #[couture(prompt, editor)] asks in the user’s editor instead, for text a single line can’t hold. editor(extension = "md") names the temp file’s extension, txt by default, so the editor highlights it.

use clap::Parser;
use clap_couture::{Couture, CoutureParser};

#[derive(Parser, Couture)]
struct Cli {
    /// Release notes
    #[arg(long)]
    #[couture(prompt, editor(extension = "md"))]
    notes: String,
}

let cli = Cli::couture_parse();

The editor is found as git finds its own: $VISUAL (unless TERM says the terminal is dumb), then $EDITOR, then vi, and : takes the file as written. Its string is split into words like a shell would, so EDITOR="code --wait" works, but ~ and variables in it are not expanded. A known editor that returns at once, like code, gets the flag that makes it wait; any other that returns right away without touching the file is asked about before its answer is taken.

The file opens with the arg’s default, or the answer clap just turned down, above a header asking the question. The header’s lines start with #|, so it comes back out while the user’s own # lines, like markdown headings, stay. An empty file leaves an optional arg unset and aborts for a required one, like an empty commit message. It aborts for an arg with a default too, rather than quietly bringing the default back. The file is read in the encoding its byte order mark names, or as UTF-8, or else in the system’s legacy encoding: the ANSI code page on Windows, the locale’s elsewhere. A file in none of them reopens with an error.

use clap::Parser;
